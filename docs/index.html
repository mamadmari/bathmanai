یک اکوسیستم پنج‌ماژولی فارسی، بدون هیچ وابستگی npm

bathmanai مجموعه‌ای از پنج محصول مستقل است — پورتال معرفی خدمات، فروشگاه «بلوپیپر»، سامانه نوبت‌دهی «کلینیک مهر»، میز کار معاملات «کریپتودسک» و ربات دانلودر تلگرام — که روی یک سرور لینوکسی با Nginx، systemd، TLS خودکار و CDN اجرا می‌شوند و کد همه‌شان در یک ریپوی GitHub نگه‌داری می‌شود.

مشاهده سایت ↗ مخزن گیت‌هاب معماری سیستم 
# استقرار یک‌مرحله‌ای روی سرور
$ git clone git@github.com:mamadmari/bathmanai.git
$ cp deploy/nginx/bathmanai.conf \
     /etc/nginx/sites-available/
$ nginx -t && systemctl reload nginx
$ systemctl enable --now clinic cryptodesk dlbot

درباره پروژه

از یک صفحه فرود تا پنج سرویس در حال اجرا

این پروژه با یک هدف ساده شروع شد: ساخت سرویس‌های فارسی که سریع باشند، روی سرور کم‌منبع (۲ گیگ رم) بالا بیایند و نگه‌داری‌شان ساده بماند. نتیجه، مجموعه‌ای است که در آن هر ماژول یک فرآیند Node.js مستقل با صفر وابستگی خارجی است و فقط از ماژول‌های داخلی Node استفاده می‌کند.

🎯 هدف

ساخت محصولات واقعی و قابل استفاده برای کاربر ایرانی: نوبت‌دهی پزشکی، فروشگاه، ابزار تحلیل بازار و ربات دانلود — با تجربه‌ی موبایل‌فرست و راست‌به‌چپ.

🧩 رویکرد

«بدون وابستگی» به‌عنوان یک قاعده: هیچ پکیج npm، هیچ فریم‌ورک سنگین و هیچ سرویس جانبی اجباری. فقط Node.js، استانداردهای وب و ابزارهای سیستمی لینوکس.

📈 نتیجه

پنج سرویس در حال اجرا روی یک سرور، شش دامنه با TLS معتبر، استقرار تک‌دستوری، بکاپ‌گیری منظم و کد یکپارچه در GitHub — بدون هزینه‌ی زیرساخت اضافه.

معماری سیستم

مسیر یک درخواست، از مرورگر تا دیتابیس

ترافیک کاربران ابتدا به لبه‌ی CDN می‌رسد و از آنجا به سرور مبدأ (آلمان) هدایت می‌شود. Nginx بر اساس دامنه، درخواست را یا مستقیم از فایل‌های استاتیک سرو می‌کند یا به یکی از سه سرویس Node.js روی پورت‌های محلی پروکسی می‌کند. هیچ پورتی جز ۸۰ و ۴۴۳ از بیرون باز نیست.

مسیر کاربر لبه شبکه (CDN) کد و استقرار فایل استاتیک خط‌چین: ارتباط خارجی یا غیرهمزمان
ماژول‌ها

امنیت

پیش‌فرض‌های محافظه‌کارانه

هیچ رمز، توکن یا کلیدی داخل کد نیست؛ همه از فایل محیطی با دسترسی 600 خوانده می‌شوند.

🛡 لایه شبکه

  • فقط پورت‌های ۸۰ و ۴۴۳ عمومی؛ سرویس‌ها روی 127.0.0.1 گوش می‌دهند
  • TLS نسخه ۱.۲ و ۱.۳ با گواهی Let's Encrypt و تمدید خودکار
  • فایروال UFW با سیاست deny پیش‌فرض
  • ورود SSH فقط با کلید (پسورد غیرفعال)

🔑 لایه اپلیکیشن

  • هدرهای X-Content-Type-Options، X-Frame-Options، Referrer-Policy
  • هش رمز عبور با crypto.scrypt و مقایسه‌ی زمان‌ثابت
  • امضای کوکی نشست و اعتبارسنجی ورودی در همه‌ی APIها
  • محدودیت نرخ روی مسیرهای حساس و احراز هویت

🗄 داده و رازداری

  • متغیرهای حساس در /etc/dlbot.env با مجوز 600 و خارج از مخزن
  • الگوی .env.example در ریپو بدون مقدار واقعی
  • بکاپ منظم دیتابیس و فایل‌های داده پیش از هر تغییر
  • داده‌ی کاربران و فایل‌های دانلودشده در gitignore

🧭 عملیات

  • گیت‌هاب با Deploy Key اختصاصی و دسترسی نوشتن محدود به همین مخزن
  • بکاپ‌گیری قبل از هر تغییر با نام زمانی و امکان بازگشت سریع

استقرار و نگه‌داری

از git push تا سرویس زنده

فرآیند استقرار به‌صورت اسکریپت و مستند در مخزن نگه‌داری می‌شود تا هر تغییر قابل بازتولید باشد.

کد در مخزن

تغییر روی برنچ main ثبت و با Deploy Key به GitHub فرستاده می‌شود.

دریافت روی سرور

git pull یا rsync فایل‌ها را در مسیر نهایی قرار می‌دهد.

کانفیگ سرویس

vhost و unitها از پوشه‌ی deploy/ کپی و با nginx -t اعتبارسنجی می‌شوند.

راه‌اندازی و ریلود

systemctl reload nginx و systemctl restart <app> بدون قطعی محسوس.

بررسی سلامت

تست /api/health هر اپ و بررسی کد ۲۰۰ روی هر دامنه با curl.

بکاپ و برگشت

آرشیو زمانی از داده و کانفیگ؛ بازگشت با یک دستور در صورت خطا.

# 1) دریافت کد جدید
git -C /srv/bathmanai-repo pull --ff-only
# 2) کپی کانفیگ‌ها و تست انجینکس
cp /srv/bathmanai-repo/deploy/nginx/*.conf \
   /etc/nginx/sites-available/
nginx -t && systemctl reload nginx
# 3) بازراه‌اندازی سرویس‌ها
systemctl restart clinic cryptodesk dlbot
# 4) تست سلامت
curl -s -o /dev/null -w '%{http_code}\n' \
   -H 'Host: clinic.bathmanai.ir' http://127.0.0.1/api/health
# 5) بررسی گواهی و تمدید
certbot renew --dry-run
